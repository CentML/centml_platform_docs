---
title: 'Securing Endpoints'
description: 'How to protect your inference endpoints with Bearer tokens and mTLS certificates'
---

NVIDIA CCluster does not expose public endpoints. Every General Inference and Dynamo deployment must be protected, and clients must authenticate on each request. You secure a deployment with **at least one** of the following:

- **Bearer token** — an `Authorization: Bearer <token>` header on each request.
- **mTLS client certificate** — a TLS certificate the client presents on each request.

<Note>
Endpoint bearer tokens (from your [Secrets](/resources/vault)) are not the same as [service account](/resources/service-accounts) credentials. Service accounts authenticate automation to NVIDIA CCluster platform APIs; bearer tokens from Secrets protect calls to your deployed endpoints.
</Note>

You choose the protection method when configuring a deployment. You may enable both for defense in depth.

## Bearer token access

Generate a Bearer token from your [Secrets](/resources/vault), then include it in the `Authorization` header of every request.

The request path comes from the server running in your deployment. The examples use `/v1/chat/completions`, which OpenAI-compatible servers such as vLLM, TensorRT-LLM, NIM, and Dynamo expose. If your container serves a different API, use its path.

**Using curl command**
```bash showLineNumbers={false}
curl -X 'POST' 'https://<endpoint_url>/v1/chat/completions' \
  -H 'Authorization: Bearer <your_bearer_token>' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "messages": [
    {
      "role": "user",
      "content": "what is the meaning of life?"
    }
  ],
  "model": "meta-llama/Llama-3.2-3B-Instruct",
  "max_tokens": 512
}'
```

**Using OpenAI client library**
```python
from openai import OpenAI

client = OpenAI(
    api_key="<your_bearer_token>",
    base_url="https://<endpoint url>/v1",
)
```

## mTLS certificate access

When configuring a deployment, under **Private Endpoint**, choose **Certificate**. Then select an existing certificate, or select **+ Add a new certificate** to generate one or use your own. When you generate a new certificate, its `.pem` file downloads to your browser at that moment, and the certificate is saved to your [Secrets](/resources/vault). Access to the endpoint then requires the HTTP client to present this certificate. Here are a few examples:


**Using curl command**
```bash showLineNumbers={false}
# --cert points to the .pem file downloaded when you generated the certificate
curl -X 'POST' 'https://<endpoint_url>/v1/chat/completions' \
  --cert <path to TLS certificate> \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "messages": [
    {
      "role": "user",
      "content": "what is the meaning of life?"
    }
  ],
  "model": "meta-llama/Llama-3.2-3B-Instruct",
  "max_tokens": 512,
  "n": 1,
  "presence_penalty": 0,
  "stream": true,
  "stream_options": {
    "include_usage": true
  },
  "temperature": 0.7,
  "top_p": 1
}'
```



**Using httpx library**
```python
import httpx

client = httpx.Client(cert="<path to TLS certificate>")
```

**Using OpenAPI client library**
```python
import httpx
from openai import OpenAI

client = OpenAI(
    api_key="no_key",
    base_url="https://<endpoint url>/v1",
    http_client=httpx.Client(cert="<path to TLS certificate>"),
)
```
